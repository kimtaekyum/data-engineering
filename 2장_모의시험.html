서술형 2문항, 각 5점

서술형 1 벡터화

Python loop와 NumPy ufunc 비교

Python 반복문으로 배열의 각 원소를 처리하는 방식과 NumPy ufunc를 이용한 벡터화 연산을 비교하시오. 대량 데이터 처리 관점에서 어떤 방식이 더 적절한지도 함께 서술하시오.

모범 답안 방향

Python 반복문은 배열의 원소를 하나씩 꺼내 계산하는 방식이고, NumPy ufunc는 배열 전체에 같은 연산을 벡터화하여 적용하는 방식이다. ufunc는 NumPy 내부의 최적화된 연산을 사용하므로 원소 수가 많을수록 반복문보다 빠르고 코드도 간결하다. 예를 들어 백만 개의 센서 데이터에 역수나 보정값을 적용할 때 1 / big_array처럼 한 줄로 처리할 수 있다. 데이터 엔지니어링 관점에서는 대량 데이터를 반복적으로 처리하는 상황이 많기 때문에 벡터화 연산이 처리 속도와 유지보수 측면에서 중요하다.

채점 포인트: 반복문과 ufunc 차이, 벡터화, 속도, 대량 데이터 처리 관점이 들어가면 좋다.
서술형 2 view/copy

슬라이싱의 view 특성

NumPy 배열에서 슬라이싱 결과가 view로 동작할 수 있다는 말의 의미를 설명하시오. 원본 데이터가 바뀔 수 있는 이유와, 이를 피하고 싶을 때 사용하는 방법을 함께 서술하시오.

모범 답안 방향

NumPy 배열의 슬라이싱 결과는 원본 배열의 데이터를 새로 복사하지 않고 같은 메모리 영역을 참조하는 view가 될 수 있다. 이 경우 슬라이스 배열의 값을 수정하면 원본 배열도 같은 데이터를 공유하므로 함께 바뀐다. 예를 들어 arr_sub = arr[:2, :2]로 만든 뒤 arr_sub[0, 0]을 수정하면 원본 arr의 해당 위치도 바뀔 수 있다. 원본 변경을 피하고 싶다면 arr[:2, :2].copy()처럼 명시적으로 복사본을 만들어야 한다.

채점 포인트: 메모리 공유, 원본 변경 가능성, copy() 사용 이유를 설명하면 좋다.
