arr = np.arange(9).reshape(3, 3)
sub = arr[:2, :2]

해설 보기

출력값은 99이다. NumPy 슬라이싱은 복사본이 아니라 원본 배열의 일부를 참조하는 view가 될 수 있다. 따라서 sub를 수정하면 같은 메모리 영역을 공유하는 arr도 바뀐다. 원본 변경을 피하려면 arr[:2, :2].copy()를 사용한다.

문제 0-1 UFunc

Python loop와 NumPy 벡터화 비교

다음 두 방식은 배열의 각 원소에 대해 역수를 계산한다. 두 방식의 차이를 설명하고, 대량 데이터 처리에서 NumPy ufunc가 더 유리한 이유를 서술하시오. 
def compute_reciprocals(values):
    output = np.empty(len(values))
    for i in range(len(values)):
        output[i] = 1.0 / values[i]
    return output

big_array = np.random.randint(1, 100, size=1000000)

compute_reciprocals(big_array)
1 / big_array
해설 보기

compute_reciprocals는 Python 반복문으로 원소를 하나씩 처리한다. 반면 1 / big_array는 NumPy의 ufunc를 이용한 벡터화 연산으로, 배열 전체에 같은 연산을 한 번에 적용한다.

대량 데이터에서는 Python 반복문보다 NumPy 내부의 최적화된 C 기반 연산이 훨씬 빠르다. 데이터 엔지니어링 관점에서는 센서 데이터나 로그 데이터처럼 큰 배열을 처리할 때 벡터화 연산이 처리 시간과 코드 복잡도를 줄여준다.

axis 방향 해석

다음 2차원 배열에서 np.sum(arr, axis=0)과 np.sum(arr, axis=1)의 결과를 예측하고, axis가 의미하는 바를 설명하시오. 
arr = np.array([[1, 2, 3],
                [4, 5, 6]])
해설 보기

np.sum(arr, axis=0)은 행 방향을 따라 내려가며 열별 합계를 구하므로 결과는 [5, 7, 9]이다. np.sum(arr, axis=1)은 열 방향을 따라 가로로 더해 행별 합계를 구하므로 결과는 [6, 15]이다.

import numpy as np

A = np.ones((4, 1, 3))
B = np.arange(3)

A + B
  1. 두 배열의 shape을 오른쪽부터 비교하시오.
  2. 연산 결과의 shape을 예측하시오.
  3. 데이터 엔지니어링에서 브로드캐스팅이 유용한 이유를 서술하시오.
해설 보기

A의 shape은 (4, 1, 3)이고 B의 shape은 (3,)이다. 오른쪽부터 비교하면 마지막 차원은 3과 3으로 같으므로 가능하다. 그 앞의 차원은 A가 1이고 B는 없는 차원이므로 B를 (1, 1, 3)처럼 생각할 수 있다. 따라서 결과 shape은 (4, 1, 3)이다.

데이터 엔지니어링 관점에서는 대량 데이터에 같은 기준값, 보정값, 스케일 값을 반복문 없이 적용할 수 있어 처리 속도와 코드 간결성에 장점이 있다.

문제 5 loc / iloc

명시적 인덱스와 암묵적 인덱스

다음 Series에 대해 ser.loc[2:6], ser.iloc[2:6], ser[2]의 결과를 각각 쓰고 차이를 설명하시오. 
import pandas as pd

ser = pd.Series(['red', 'blue', 'green', 'black', 'white'],
                index=[0, 2, 4, 6, 8])
해설 보기

ser.loc[2:6]는 명시적 인덱스 라벨 2부터 6까지 포함하므로 blue, green, black이 나온다. ser.iloc[2:6]는 위치 기준 2번째부터 5번째 직전까지 선택하므로 실제로는 위치 2, 3, 4인 green, black, white가 나온다. ser[2]는 이 경우 명시적 인덱스 라벨 2를 참조하므로 blue가 나온다.

핵심은 loc는 라벨 기준이고, iloc는 정수 위치 기준이라는 점이다.

API는 서비스 제공자가 정해둔 URL과 파라미터를 통해 구조화된 데이터를 받는 방식이다. 보통 JSON처럼 분석하기 쉬운 형태로 제공되므로 안정적이고 자동화에 적합하다. 반면 호출 횟수 제한, 인증 키, 제공 범위 제한을 고려해야 한다.

웹스크래핑은 HTML 페이지에서 직접 데이터를 추출하는 방식이다. API가 없는 웹페이지에서도 데이터를 얻을 수 있지만, HTML 구조가 바뀌면 코드가 쉽게 깨질 수 있고 사이트 정책을 확인해야 한다. 데이터 엔지니어링 관점에서는 수집 안정성, 법적/윤리적 문제, 자동화 가능성, 오류 처리 방식을 함께 고려해야 한다.

문제 16 시험 7장

Resampling과 Rolling 비교

시계열 센서 데이터에서 resampling과 rolling이 각각 어떤 목적에 사용되는지 설명하고, 둘의 차이를 서술하시오.
답안 방향 보기

resampling은 시간 단위를 바꾸어 데이터를 집계하는 작업이다. 예를 들어 분 단위 센서 데이터를 시간 단위 평균으로 바꾸는 경우가 해당된다. rolling은 일정한 크기의 이동 창을 사용해 이동 평균 같은 값을 계산하는 방식이다. 데이터 엔지니어링 관점에서 resampling은 시간 해상도 조정에, rolling은 시계열의 추세나 노이즈 완화에 유용하다.

답안 방향 보기

결측치 제거는 구현이 간단하고 잘못된 값을 넣지 않는다는 장점이 있지만, 데이터 수가 줄어들고 특정 패턴의 행이 사라져 편향이 생길 수 있다. 결측치 대치는 데이터 크기를 유지할 수 있지만, 평균 대치나 이전값 대치가 실제 값을 완벽히 복원하는 것은 아니므로 분산이나 추세가 왜곡될 수 있다. 시계열 데이터에서는 이전 시점의 값이 다음 값과 관련될 수 있어 forward fill이 의미 있을 수 있지만, 급격한 변화가 있는 데이터에서는 주의가 필요하다.

문제 18 시험 9장

IQR 기반 이상치 탐지

IQR 기반 이상치 탐지에서 Q1, Q3, IQR의 의미를 설명하고, 일반적으로 어떤 기준으로 이상치를 판단하는지 서술하시오.
답안 방향 보기

Q1은 1사분위수, Q3는 3사분위수이고, IQR은 Q3 - Q1로 데이터의 중간 50% 범위를 의미한다. 일반적으로 Q1 - 1.5 * IQR보다 작거나 Q3 + 1.5 * IQR보다 큰 값을 이상치 후보로 판단한다. IQR 방식은 평균과 표준편차보다 극단값의 영향을 덜 받기 때문에 분포가 완전히 정규적이지 않은 데이터에서도 유용하다.
